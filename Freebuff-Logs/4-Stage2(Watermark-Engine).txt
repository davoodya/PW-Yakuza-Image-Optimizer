## Stage 2 Complete ✅ — Watermark Engine

**What was built (`includes/watermark.php`):**
- **`yio_apply_watermark()`** — self-gating entry point: if both `watermark_enable` and `text_enable` are off, the image passes through untouched. All engine errors are swallowed and logged, so a watermark failure can never break the upload pipeline.
- **`yio_apply_image_watermark()`** — loads the watermark PNG by attachment ID, scales its width to the configured `watermark_scale` % (never exceeding image dimensions), fades it via alpha-channel multiply (`watermark_opacity`), and composites it at one of 9 positions with `watermark_padding`. Includes guards for a missing watermark file and for the pathological case where the image being processed *is* the watermark.
- **`yio_apply_text_watermark()`** — renders `text_content` on a transparent canvas, trims it to its tight bounding box, fades it (`text_opacity`), and composites it at `text_position`. Color is hex-validated with a safe `#FFFFFF` fallback.
- **`yio_watermark_position()`** — shared 9-position math with clamping, used by both engines.

**Validation (local PHP has no Imagick, so I validated three layers):**
- `php -l` passes on all files.
- **11/11 unit tests** passed on the position math (all 9 positions + oversized-stamp clamping + unknown-position fallback).
- **Algorithm proven with the ImageMagick 7.1 CLI** mirroring the engine's exact operations: the stamp center pixel came out to the *exact* expected 50% blend `srgb(153,51,76)` of red over `#336699`; the untouched area stayed pure; a transparent PNG stamp's border pixels stayed clean — proving `ALPHACHANNEL_SET` + alpha-multiply fades a watermark **while preserving its shape** (and uniformly fades JPEG stamps); text render→trim produced a tight 136×22 bounding box, and the composited text changed 1125 pixels with correct blending.
- Code review passed; applied its one worthwhile suggestion — the text canvas is now sized from a generous 1.2em/byte estimate instead of the full image, avoiding a transient multi-MB allocation on huge sources when smart-resize is off.
