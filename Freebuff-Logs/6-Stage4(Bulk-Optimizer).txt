## Stage 4 Complete ✅ — Bulk Optimizer

**The engine (`includes/bulk.php`, new):**
- **AJAX-driven batched processing** — `yio_bulk_start` scans the library, `yio_bulk_step` processes one batch per request (`bulk_batch_size`, default 20), `yio_bulk_status` reports progress, `yio_bulk_cancel` pauses. Every handler is protected by a nonce + `manage_options` capability check.
- **All five settings honored**: `dry_run` (scans and logs only, nothing touched), `bulk_limit` (caps the queue), `include_webp` (excludes already-converted files from the scan), `bulk_batch_size` (per-request batch), and `background_processing` (WP-Cron continuation so a run survives closing the tab — the AJAX driver and cron serialize via an atomic lock with stale-steal recovery).
- **Robustness**: the queue lives in a transient, state in an option, each image is wrapped in its own try/catch so one failure can't abort the run, and results are bucketed into optimized/skipped/failed with total bytes saved tracked for the summary.
- **Correct DB handling**: bulk stores the pipeline's returned metadata via `wp_update_attachment_metadata()` (which the upload flow does automatically) — the same rollback-safe ordering from Stage 1 means the DB can never point at a deleted file.

**Critical supporting fix (`image-processor.php`):** bulk calls `yio_optimize_single_image()` directly, bypassing the upload filter — and the pipeline's internal size-regeneration re-fires the metadata filter, which would otherwise re-run the entire pipeline once per image. Added a re-entrancy guard (wrapped in `try/finally` so it resets on every path) around the pipeline, which makes nested calls no-op.

**The UI (`includes/admin/bulk.php`):** Start / Pause / Resume buttons, an animated progress bar, a live counter, a scrolling log of the last 30 results, and a done-summary showing bytes saved. It also shows the current image count in the library, and on page load it polls status — so if cron finished or continued a run in the background, the tab reattaches and shows the real state. Settings inputs now have IDs so the Start button persists the current form values (sanitized) before scanning.

**Validation:** `php -l` passes on all files; the inline JS passed a `node --check` syntax check; code review confirmed the guard/finally correctness, the unchanged-detection logic (`$new_metadata === $metadata`), cron/AJAX convergence, and the nonce/cap security. Three review fixes applied: primed the meta cache in the scan (kills N+1 DB queries on large libraries), raised the lock TTL to 15 minutes (a slow batch can't have its lock stolen mid-run), and simplified the paused-state branch.
