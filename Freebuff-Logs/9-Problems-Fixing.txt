All four problems are fixed and validated. Here's what was wrong and what I changed:

## 1. Uploads broke after activating the plugin

The root cause: the plugin's filter ran on **every** `wp_generate_attachment_metadata` call — not just new uploads. WordPress lazily regenerates metadata for *existing* images (browsing the Media Library, thumbnail regeneration, imports), so the pipeline fired on those too, and `yio_log()` used an unsuppressed `file_put_contents` — a single PHP warning would corrupt the AJAX upload response and make the upload fail entirely.

**Fixes:**
- **New-upload-only marker** (`image-processor.php`): `add_attachment` now sets a transient flag; the pipeline early-returns unless that flag is present and consumes it. Existing images are **never** auto-processed, no matter what triggers metadata regeneration. Verified with a functional test: new upload → processed; existing/re-generated → skipped; marker consumed exactly once; restore-pause still works.
- **Hardened `yio_log()`**: guards the uploads dir and uses `@file_put_contents` + `LOCK_EX`, so logging can never emit output into an AJAX response.
- **Memory/time raising** inside the filter before processing (`wp_raise_memory_limit('image')`, `set_time_limit(300)`).

## 2. Watermark applied to ALL existing images — now impossible

Same root cause as #1 — the filter was running on existing images. With the marker, the pipeline runs **only** on genuinely new uploads. Existing images are now watermarked **only** when you explicitly act:
- **"Apply to All" button** in the Watermark tab — starts a watermark-only batch run (via the bulk engine in a new `watermark` mode that reuses progress bar/log/pause/resume/cron, applies the watermark without converting formats).
- **Per-image "Apply Watermark"** in the Media Library.

## 3. Per-image watermark in the Media menu

New `includes/admin/media-actions.php`: an **"Apply Watermark" row action** under each image in the Media Library list view, plus a matching **bulk action** for multiple selections. Both are nonce-protected, capability-checked, and show a success/failure notice after redirecting back. They use a new `yio_apply_watermark_existing()` engine that watermarks in place (keeping the current format), backs up the pre-watermark file first so the restore system can undo it, and regenerates sizes with the pipeline paused.

## 4. Watermark tab UI fixes

- **Media Library picker instead of ID input**: a "Select Image" button opens the standard WordPress media picker (`wp.media`), shows a thumbnail preview with a Remove button, and stores the selected attachment ID in the hidden settings field.
- **Color palette instead of hex text**: the Text Color field is now a native `type="color"` color-picker input (with a validated `#rrggbb` fallback).
